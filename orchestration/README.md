## Использование команды

Локальные terminal handles и пути профилей сохранены в `runtime.local.json`,
который исключён из Git. После перезапуска Orca адреса надо обнаружить заново;
не отправлять задания одновременно на устаревший и новый handles.

После получения кейса Claude загружает версионный навык orchestration,
создаёт и связывает Run, распределяет владение файлами и назначает задания
готовым исполнителям через `worker-start --terminal <handle> --worktree <selector>`.
Модель/effort при переиспользовании terminal не передаются.
Свежие сессии без явной привязки профиля могут использовать одинаковый аккаунт:
не заменять готовых исполнителей двумя обычными `--agent codex`.

Подготовленные terminals ожидают кейс по просьбе пользователя. Они пока не
являются Dispatch workers: после первого назначения обязательны Task/Dispatch
контракт и settlement/cleanup из актуального навыка Orca.

Работать параллельно только над независимыми задачами. Писать короткие,
самодостаточные задания с критериями приёмки; использовать одного исполнителя,
если задача мала. Не опрашивать агентов без причины и не выполнять повторно
проверенные работы. При лимитах сохранять контекст и уточнять добавление резерва.

Дополнительный Codex подключается через Accounts Orca или
`orca account add --agent codex`. После подключения обновить распределение
аккаунтов и передать сохранённый контекст задачи по контракту `AGENTS.md`.

Подготовленные инструкции не являются работающим автоматическим планировщиком
или системой автоматического переключения аккаунтов.
