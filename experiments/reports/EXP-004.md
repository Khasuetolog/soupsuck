| `unpad.py`: helper's final transpose+contiguous followed by concatenation | Use the same masked CUDA SDPA inputs/scaling/GQA repeat; append the transpose view and copy once in final cat | **0–112 copies**, layout-dependent; **do not assume 112 on T4** | SDPA arithmetic/backend settings unchanged. | `autograd.py`: pad/scatter argmax solely for accuracy | Count correct/labelled directly against certified shifted packed targets | **1 long Fill + 1 Opaque8 index_copy kernel** | Integer counts identical; ignored final/pad targets do not contribute. Loss/entropy scatters remain unchanged. |

Thus the conservative expected saving is **56 DtoD transfers + 3 small
kernels/step**, plus only those SDPA layout copies that actually exist.
No claim is made that 112 SDPA copies exist in this T4 backend. For an
unpacked batch the argmax scatter was already absent; its saving is zero.
For noncertified LoRA modules clone stays. Existing scalar/int reductions
may use different grid sizes on packed targets but not different values.

[PyTorch 2.11 Copy.cu](https://github.com/pytorch/pytorch/blob/v2.11.0/aten/src/ATen/native/cuda/Copy.cu#L244-L300)
routes same-dtype contiguous copying through DtoD memcpy; other layouts use
copy kernels. [Efficient attention wrapper](https://github.com/pytorch/pytorch/blob/v2.11.0/aten/src/ATen/native/transformers/cuda/attention.cu#L966-L1013)
transposes its native BLHD result into BHLD. This is why the helper's inverse
transpose/contiguous may already require no CUDA copy. A profiler delta, not
the Python spelling `.contiguous()`, determines its actual launch count.

## Why removing PEFT's clone is safe in the certified route

PEFT's original clone protects subsequent manipulation of a bnb view.
Our existing LoRA epilogue (`solution/kernels/lora_epilogue.py`) instead
allocates a **new** output and only `tl.load`s Base; it never mutates result.
Its backward returns grad-to-base and a separate adapter gradient; no saved
base activation is overwritten. Frozen base and direct A/B projections with
no forward/backward hooks are required for clone removal. Unknown instance
forward overrides retain the clone; the known unpad Dropout bind is permitted
because it scatters **its own input** and never mutates the base result.

The checker additionally keeps actual base results alive, snapshots `_version`,
asserts versions unchanged after adapter **and backward**, asserts epilogue
output has a different data_ptr, and verifies epilogue receives original base
storage only in the trimmed path. This is stronger than assuming a clone is
useless because its shape matches. Arbitrary globally monkeypatched in-place
module implementations are outside the certified original-module contract.

## Operations deliberately retained

- Zero padding before native dropout: required to expose the same contiguous
  fp32 B,S,H geometry and preserve RNG. Empty without writing pad values is
  not equivalent. Pad hidden/stat values remain zero.
- Half input → fp32 before dropout and embedding gather → fp32: required dtype
  and RNG/residual semantics. No early/later rounding was introduced.
- Decoder residual sums and backward accumulations: real arithmetic and saved
  input lifetimes; no in-place update or reassociation.
- RoPE: its CUDA fast path already writes fresh outputs without Python casts.
  Dense evaluator fallback and noncontiguous inputs retain their guards.
- MLP anchors/staging/event waits: outside ownership; initialization cannot
  simply be deleted without preserving autograd edges and stream lifetime.
- CE accumulation zeros/ignored-row scatter: needed mathematical values.
  FP16 CE weight casts are already no-ops for the losslessly compressed table.
- Existing cat+reshape+contiguous: cat is necessary to join rows; its following
  contiguous is generally a no-op. No saved launch is counted for removing
  a no-op call, and no global padding policy/cache is changed.

H=64, two layers, q/v LoRA p=0.05 with nonzero B, seeds 1/7, offload off/on.
For each model compare flag 0 vs 1 with identical weights/RNG/inputs:

- bytewise loss, token loss, entropy, correct, labelled and token count;
- bytewise every LoRA A/B gradient and final CUDA RNG state;
- identical SDPA input values, shapes, dtypes, strides, mask/scaling/kwargs;
- `_version`/alias assertions proving read-only base consumption.

No allclose tolerances are used. A mismatch rejects this variant rather than
raising a threshold. Each checker process creates an empty temporary
TRITON_CACHE_DIR before imports and removes it afterward; caches are not
carried to measured training runs. This checker is validation, not a speed
benchmark: it intentionally clones observed tensors for comparison.
