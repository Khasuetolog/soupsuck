# EXP-011 — единый T4 sweep launch geometry

Статус: инструмент готов; **GPU timings, GPU bitwise checks и лучшие
конфигурации пока NOT RUN**. Production configs и `solution/` не изменены.
Коммитов, uploads и запусков Kaggle исполнитель не делал.

## Что запускается

Существующий notebook `--mode bench` уже вызывает
`tools/kaggle/bench_kernels.py`; новый mode не нужен. Команда текущего runner
называется **`run`**, не `launch`. В `run.py` добавлен только вывод новой
сводки из JSON при скачивании bench artifacts; прочие modes не менялись.

По умолчанию один процесс на GPU 0 / Tesla T4 строит **127 случаев и 2680
конфигураций** для всех **16 JIT entrypoints**. Данные синтетические с seed290,
формы соответствуют Qwen2.5-1.5B; модель и датасет не загружаются.

| Семейство | Формы и варианты |
| --- | --- |
| Fused CE | N800/801/2048; реальные chunks4096 и tail384, first/continuation statistics, outputs, derivative |
| RMSNorm/add+RMSNorm | H1536; fp32 residual/weight, fp16/fp32 outputs; input backward, первый frozen-residual и обычный add backward |
| Optional RMSNorm dgamma | partial/finalize, фиксированные 32-row boundaries; эти kernels не являются hot path frozen gamma |
| SwiGLU fused | I8960; forward/backward; fp16 и fp32 outputs; backward читает compressed fp16 gate/up |
| NF4 decode | default и fast, nested/flat; weights1536×1536,8960×1536,1536×8960,256×1536 |
| RoPE | Q12/K2 heads, D128; packed B1/T800/801/2048 и B4/T200/512; fp16/fp32/mixed forward/backward |
| LoRA epilogue | widths1536 и256, fp16/fp32 base, fp16 adapter, scale2; add/gradient |

Перебираются валидные BLOCK/ROWS/COLS/WIDTH, num_warps2/4/8 и
num_stages1/2/3. Полная неизменённая baseline-конфигурация всегда идёт первой.
У fast NF4 исходный kernel содержит static_assert BLOCK4096: без изменения
production source можно перебирать только warps/stages. Это явно записано
в плане и результатах; недопустимые BLOCK не выдаются за кандидаты.

## Исправления исходного S-029

- У CE больше не принудительно выключается fusion: его implicit production
  default сохраняется. Остальные JIT сохраняют explicit `enable_fp_fusion=False`.
- Baseline tail384 statistics использует BLOCK512, full chunk — BLOCK4096.
  Tail не ошибочно тестируется как первый chunk, Start tail равен151552.
- У LoRA и CE outputs/derivative baseline сохраняет implicit num_warps;
  кандидаты задают warp/stage значения явно.
- CE target-hit и ignore ветки выполняются в каждом chunk; mutable State/Best
  сбрасываются перед каждым correctness/warmup/timing вызовом.
- Добавлен отсутствовавший fast NF4; все его кандидаты дополнительно должны
  совпасть с baseline byte decoder, а не только с самим fast kernel.

## Точность, время и память

Сравниваются **байты каждого output**, включая fp32 промежуточные State/Rstd,
int64 argmax, signed zero и NaN payloads. Допуски не используются. Перед
validation pure outputs заполняются NaN/sentinel, чтобы неполная запись не
прошла за счёт старых значений; stateful CE получает исходный seed state.
Повторная проверка выполняется после timing. Любое несовпадение исключает
кандидат из ранжирования, с byte mismatch counts и причиной в JSON.

Compilation, validation, output snapshots и warmup находятся вне CUDA-event
интервала. На каждую допустимую конфигурацию — 5 warmups и20 event samples,
median/p10/p90/min и полный samples_ms. Сброс stateful CE также до start event.
Это warm microbenchmark; он не оценивает cold compilation cost в soup wall.

Output tensors фиксированы и переиспользуются. Сохраняются n_regs/n_spills,
shared/global/profile scratch metadata и delta PyTorch tensor allocations.
Рост global/profile scratch, spills или живых tensor bytes относительно
baseline исключает кандидат. Shared/register данные остаются в отчёте для
анализа occupancy. **Физический NVML training peak этим не доказан**:
`physical_peak_verified=false`; GPU code size и весь model allocator требуют
отдельного paired training контроля. Никакая конфигурация не применяется
к production, поэтому текущая production memory и численные результаты
вообще не меняются.

Compile/resource errors сохраняются как отказы. Обычная ошибка baseline
отмечает случай failed и позволяет получить остальные результаты; poisoned
CUDA context (illegal access/assert/misalignment/launch failure) останавливает
sweep. JSON атомарно сохраняется после каждого случая, traceback — при сбое.
Используется свежий временный Triton cache только для microbenchmark, который
удаляется при выходе и никогда не передаётся training.

## JSON output

`out/bench_kernels.json`, schema2:

- `cases`: baseline, compiler options, shape, все кандидаты, ошибки/отказы,
  exact/eligible, timings, resources, победитель случая.
- `table`: компактные строки kernel+case+shape, baseline_config, best_config,
  baseline_ms, median_ms, speedup, exact, separated_samples.
- У fast NF4 строки также содержат `default_decoder_ms` и
  `speedup_vs_byte_decoder` для matched default case.
- `best_by_kernel`: один common_config только если он допустим и побитово
  точен **на всех формах/dtypes/phases этого JIT**. Выбор — минимальный
  equal-weight geometric mean relative time; это не training speedup.
  Если общей конфигурации нет, common_config=null с причиной, case table
  остаётся доступной. Разные winners не склеиваются в несуществующий config.
- Legacy `best` сохранён для прежнего consumer. `run.py` печатает и новую
  per-kernel сводку, и прежние case winners.

`separated_samples` означает best p90 < baseline p10; это диагностический
признак, **не CI и не критерий автоматического promotion**. Результат одного
microbenchmark не заменяет paired end-to-end A/B/full2/check_rules.

## Команда координатору

После принятия source commit и обновления private code dataset (runner
использует только committed HEAD), при свободной GPU reservation:

```sh
python3 tools/kaggle/run.py run --mode bench --tag exp011
```

Внутри подготовленного Kaggle checkout тот же полный sweep можно вызвать:

```sh
python tools/kaggle/bench_kernels.py --out /kaggle/working/out --rows 800 801 2048 --stages 1 2 3 --warmup 5 --repeats 20
```

`--kernels <comma-separated exact names>`, `--rows`, `--stages` позволяют
повторить выбранные случаи. Полный default sweep уже подключён к существующему
notebook без правок `.ipynb` и без новых modes. Проверить top configs повторно,
затем назначить отдельную production задачу с paired A/B: EXP-011 сам configs
не продвигает. Kaggle runtime/победители пока UNVERIFIED.
