## Implementation

Files: `tools/kaggle/run.py`, `tools/kaggle/iterate.ipynb`, `tools/kaggle/registry.py`.
The submitted dataset still contains committed HEAD only, verified against the source
manifest. The coordinator must commit these files before `push-code`/a real run.
Existing runner modes retain their commands and defaults.

`run --mode ab --variants 'A=;B=SOUP_EXP_NAME=1' --rounds R` generates **one private
T4 notebook/session**. The notebook installs the usual pinned packages, verifies the
archive SHA, prepares data once, then invokes the registry runner. GPU work is strictly
sequential through blocking subprocess calls:

```text
python harness/run_task.py --only base     --out <ab>/runs/000_r00_base
python harness/run_task.py --only solution --out <ab>/runs/001_r01_A
python harness/run_task.py --only solution --out <ab>/runs/002_r01_B
python harness/run_task.py --only solution --out <ab>/runs/003_r02_B
python harness/run_task.py --only solution --out <ab>/runs/004_r02_A
... repeat forward/reversed order for subsequent rounds
```

For three variants the schedule is `base; A,B,C; C,B,A; A,B,C; ...`.
There is exactly one base and one official solution training/evaluation per variant per
round. No extra profile training run is requested. `harness/_train.py` is reached only
by the unchanged official `harness/run_task.py`; no direct training calls, changed
trainer arguments, altered rows, or altered seeds are introduced.

Controls and caches:

- A must be first and empty: `A=`. Variant labels are unique; `base` is reserved.
- Candidate assignments are comma-separated, and accept only `SOUP_EXP_NAME=1`.
  Multiple flags: `B=SOUP_EXP_X=1,SOUP_EXP_Y=1`. Empty B is permitted for an A/A control.
- `--env` is rejected in A/B mode. Inherited `SOUP_*` switches are removed before
  each official process; only that variant's explicitly specified flags are added.
  The official harness then applies its usual required environment itself.
- Output roots cannot be reused. Every run gets a fresh output directory;
  `run_task.train()` removes/recreates `base_1`/`solution_1` and assigns its empty
  `TRITON_CACHE_DIR` and `TORCHINDUCTOR_CACHE_DIR` (see `harness/run_task.py`, `train`).
  Inherited compiler-cache overrides are removed. There is no cross-run compilation
  cache reuse and no precompile/warmup outside what the official harness does.
- Once evaluation and evidence extraction finish, trained adapters and compiler caches
  are deleted. JSON, logs, generated task config and plan remain. The notebook repeats
  adapter/cache cleanup in `finally`, including interrupted/error runs.

## Evidence and metric definitions

Remote layout, downloaded beneath `runs_kaggle/<AB_RUN>/out/`:

```text
ab/plan.json                         # variants, ordered calls, rounds, session, SHA, config hash
ab/summary.json                      # per-session medians and paired intervals
ab/runs/<order>_r<round>_<label>.log  # official harness stdout/stderr
ab/runs/<order>_r<round>_<label>/result.json
ab/runs/<order>_r<round>_<label>/{base,solution}_1/{metrics.json,train.log,...}
ab/runs/<order>_r<round>_<label>/eval_{base,solution}.json
experiments/registry.jsonl
experiments/results.csv
status.json                          # notebook command statuses
```

Each attempted official run appends one schema-1 JSONL record immediately. Its stable
`run_id` combines session, configuration digest and execution order. Records include
commit/session/env/round/order, commands, exit codes, task seed/files, library versions,
artifact paths, and the following values:

| Field | Official source / definition |
|---|---|
| `wall_s` | `result.json: runs[side][0].wall_s`, whole `soup train` process; **not** runner subprocess elapsed |
| `loop_s` | `<side>_1/metrics.json: train_loop_s` |
| `first_step_s` | `<side>_1/metrics.json: step_s[0]`; `run_task.py` removes this array from its embedded metrics, so the original file is read |
| `median_step_s` | `<side>_1/metrics.json: median_step_s` |
| `peak_mib` | `result.json: runs[side][0].gpu_peak_mib`, official external GPU poller |
| `eval_loss` | `result.json: evals[side].mean_loss` |
| `timed_loop_s` | `<side>_1/metrics.json: timed_loop_s` |
| `own_share` | sum of `own_kernel_ms` excluding example/Inductor prefixes, divided by `1000 * timed_loop_s`; a fraction, **not** a percentage |

`own_share` is a diagnostic proxy, not check 4 certification: the jury additionally
checks similarity to the example. `harness_wall_s` separately records the full harness
subprocess including warmup/evaluation, and is never substituted for `wall_s`.
The complete per-name own-kernel milliseconds are preserved in JSONL.

A row is successful only when subprocess/train/metrics/evaluation exit codes are zero,
all collected metrics are finite, the Triton watcher has no error, and the official
package-change list is empty. In particular, an official process can exit zero even
when training fails; its artifacts are checked. Missing/corrupt artifacts create a
failed row. Later variants still run for evidence collection, but failures propagate
to the notebook/local runner exit status.

After download, `run.py` imports the remote records into the repository's
`experiments/registry.jsonl` and regenerates `experiments/results.csv`. Importing the
same evidence again is idempotent; conflicting records with the same ID are rejected.
Remote paths are retained and `local_artifact_root` points to downloaded evidence.
Automatic collection rejects another session/SHA before import, and returns failure
for incomplete row counts or failed attempts while preserving valid partial evidence.
CSV keeps failed attempts and has `checks=not_run`, `decision=measurement_only`.
No synthetic measurement rows were added to either tracked registry file.

## Statistics and decisions

Aggregation groups by **session + commit + experiment + config digest**. Machines,
commits, and variant sets are never silently pooled. It prints medians for every
metric, successful/attempted counts, and paired differences from A.

For each candidate and metric, pair only successful candidate/A runs from the **same
round**. The estimate is the median of `candidate - A`, not a difference between two
unpaired medians. For wall time it also prints the median relative change in percent.
Negative time differences mean faster. The 95% descriptive interval is a percentile
bootstrap of whole round-pair differences, with 10,000 resamples and reproducible
stdlib RNG seed 303 (implementation constants, not benchmark measurements).
With fewer than two valid pairs, CI is null; no zero-width one-pair confidence claim
is made. Constant multi-round differences can still produce a degenerate interval.

Use an even round count to balance endpoint order; at least six rounds are recommended
for screening, with wider sampling if the interval overlaps zero. These small-sample
intervals do not remove within-session drift/autocorrelation or make multiple-candidate
selection statistically conclusive. Print sample counts and inspect round order.
Single-base speedup/memory ratios in CSV are descriptive context; decisions use the
paired A comparison. This mode does not run the ten jury checks or claim correctness
certification: correctness tests and `full2` + `check_rules` remain the acceptance gate
for finalists. The runner accepts a flag name but cannot prove that its implementation
actually executes; confirm variant activation from that candidate's own evidence.

Preview locally, without Kaggle calls (already exercised with a synthetic flag):

```bash

  --variants 'A=;B=SOUP_EXP_PRECOMPILE=1' --rounds 6 --tag exp-001-paired --dry-run
```

After review/commit and inclusion of the intended opt-in implementation in HEAD:

```bash
python3 tools/kaggle/run.py push-code
python3 tools/kaggle/run.py run --mode ab \
  --variants 'A=;B=SOUP_EXP_PRECOMPILE=1' --rounds 6 --tag exp-001-paired
```

The precompile flag is defined in `solution/precompile.py`; the NF4 candidate flag
is `SOUP_EXP_NF4_GEMM=1` in `solution/nf4_patch.py` / `solution/kernels/nf4_gemm.py`.
Only compare implemented/enabled candidate paths at the submitted SHA. To screen both
separately in one session:

```bash
python3 tools/kaggle/run.py run --mode ab \
  --variants 'A=;B=SOUP_EXP_PRECOMPILE=1;C=SOUP_EXP_NF4_GEMM=1' \
  --rounds 6 --tag wave-1-paired
```

Infrastructure A/A smoke test, both variants at default behavior:

```bash
python3 tools/kaggle/run.py run --mode ab --variants 'A=;B=' --rounds 2 --tag ab-smoke
```

Aggregate or recover a previously downloaded registry without resubmitting a kernel:

```bash
python3 tools/kaggle/registry.py aggregate
python3 tools/kaggle/registry.py import \
  'runs_kaggle/<AB_RUN>/out/experiments/registry.jsonl'
```

`<AB_RUN>` is the actual downloaded output directory. For direct execution **inside an
already prepared T4 checkout** (no submission, data/dependencies must exist):

```bash
python tools/kaggle/registry.py run-ab \
  --variants 'A=;B=SOUP_EXP_PRECOMPILE=1' --rounds 6 \
  --out /kaggle/working/out/ab --registry-root /kaggle/working/out/experiments \
  --session '<UNIQUE_SESSION_ID>' --commit '<FULL_COMMIT_SHA>' --experiment EXP-001
```

The direct output directory must not already exist. The unique session ID and full SHA
must describe the actual source/session; notebook mode supplies both automatically.
