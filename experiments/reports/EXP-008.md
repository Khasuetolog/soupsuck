## Single candidate selected

`solution/lora_pair.py` collapses the two vanilla LoRA Linear autograd graphs
into one first-order boundary. It targets the frequent cast/view/graph chain
identified above, not the profiler itself. It is the selected actionable
host-overhead hypothesis; whether it is the largest *actual* win is pending
trace/A/B evidence. No inspection of profiling/harness state occurs in it.

Forward under existing CUDA fp16 autocast:

```text
X16 = cast(X); A16 = cast(A); B16 = cast(B)
Z16 = F.linear(X16,A16); Y16 = F.linear(Z16,B16)
```

Backward, with each GEMM returning fp16 as in AMP Linear backward:

```text
dZ16 = g16 @ B16
dB16 = g16.T @ Z16; dA16 = dZ16.T @ X16; dX16 = dZ16 @ A16
return casts to the original input/A/B dtypes
```

Only requested derivatives are computed and only their input dependencies
saved. There is no weight cache or persistent GPU scratch; saved tensors are
the same X16/Z16/A16/B16 dependencies as the two native Linear derivatives.
The flag is checked in the existing LoRA wrapper, and the new module is not
imported with the flag absent. Dropout is still called once, in the same
order after the base projection; scaling and our rounded epilogue stay outside
the new boundary. Bias, hooks, instance overrides, unsupported precision,
noncontiguous input and non-AMP paths use the existing native pair.

No TF32/backend flags, LoRA parameters, optimizer, RNG operation, data, losses,
allocator policy or default switches changed. Higher derivatives are outside
the opt-in contract. Fewer native graph nodes can also reduce layerprof's
own overhead; **a faster instrumented probe or missing old LoRA graph buckets
is not accepted as proof of speed**. Only uninstrumented paired wall is used.

## Native attribution tool

`experiments/exp008_trace.py` runs the unchanged harness entrypoint with a
native torch CPU/CUDA profiler and a main-thread cProfile window. It adds no
Tensor/autograd-node hooks. The only module-class wrapper labels trainable
rank16 Linear forwards with record_function; constructor callback attachment
does not alter model values. Allocator/device settings are applied before
torch import to match harness. The ordinary process precompile still uses
the inherited fresh run cache; no inter-run reuse is introduced.
The supplied config is copied with only its output path redirected to the
probe's own adapter directory, so two probes do not share an output adapter.

Outputs:

- trace.json: CPU operators, CUDA runtime synchronizations, launches and GPU
  timeline; use flow events to join backward to forward.
- operators.json: calls/input shapes, self/inclusive CPU/device time and
  initial cast/elementwise/sync/SDPA/GEMM/autograd/optimizer families.
- python.pstats: main-thread eligibility/wrapper/Trainer/dispatch costs.
- metrics.json: normal harness metrics, not promoted as a performance run.

Default active window is steps9–10 after warmup; `--first-step` captures
startup through step1, including model load (separate those events from the
actual training step). CPU work of the spawned compiler child is not in the
parent's profiler. Native tracing is itself instrumented; its purpose is
attribution, not paired wall/peak acceptance. Autograd worker CPU threads are
in native trace, not main-thread cProfile.
