Статус: measurement tool и CPU-only runner mode готовы. **Фактические token
counts, padding ratios и tokenization timings пока NOT RUN**: локально нет
закреплённых Soup/TRL/torch и официального `data/train.jsonl`. Никакие числа
из self-check не являются статистикой датасета. Коммитов, uploads и запусков

Изменены только `tools/kaggle/token_stats.py`, `tools/kaggle/run.py` и этот

## Как воспроизводится pipeline

Скрипт требует версии, записанные в существующем full2: Soup 0.77.0,
transformers 5.16.1, TRL 0.29.1, PEFT 0.20.0, Accelerate 1.14.0,
datasets 4.8.5 и torch 2.11.0 (CPU/CUDA wheel suffix не меняет CPU sampler).
При расхождении версий отказывает, а не выбирает похожий API.

Используются настоящие функции библиотек:

1. `soup_cli.config.loader.load_config(task/task.yaml)` и
   `soup_cli.data.loader.load_dataset(cfg.data)`: тот же local JSONL → alpaca
   normalization → 256 train rows, без validation split.
2. `AutoTokenizer.from_pretrained` с тем же Qwen model ID, native Soup
   `base_revision_kwargs`, `trust_remote_code=False` и правилом pad=eos
   только при отсутствующем pad. Записываются resolved revision (если библиотека
   его сообщает), hash backend tokenizer и chat template.
3. `build_format_row`, `_map_text_sft_rows`, `_ensure_assistant_masks` из
   Soup: assistant/response labels вычисляет исходный formatter. Маски не
   заменяются подсчётом длины строки или отдельной tokenization approximation.
4. Native Soup `TrainingArguments → _as_sft_config` с max_length512,
   batch4, grad_accum1, seed1, epochs1, packing=False; TRL
   `SFTTrainer._prepare_dataset` выполняет тот же truncate. Data defaults
   shuffle=False, padding_free=False, pad_to_multiple_of=None проверяются.
5. Native TRL `DataCollatorForLanguageModeling` с тем же resolved pad,
   completion-only decision и assistant masks; native HF
   `get_train_dataloader` / `_get_dataloader` / `_get_train_sampler` и CPU
   Accelerate с исходным `DataLoaderConfiguration`.

Ни model loader, ни model constructor, ни Trainer constructor не вызываются.
Data-only shell класса SFTTrainer предоставляет только нужные поля native
dataset/dataloader methods. CPU placement и отключённая mixed precision нужны
для измерения на CPU; модель/optimizer/training не запускаются. Остальные
переданные training kwargs повторяют Soup, включая native seed/warmup helpers.

### Точный порядок батчей

Soup по умолчанию включает Rewind. Его настоящий `IndexRecordingSampler`
оборачивает `RandomSampler`. Это существенно: Accelerate заменяет только
`isinstance(sampler, RandomSampler)`, поэтому подмена обёрнутого sampler на
отдельный `SeedableRandomSampler` могла бы изменить порядок.

Инструмент использует `make_rewind_trainer_class(SFTTrainer)` и настоящие
RewindState/FIFO. Sampler indices извлекаются через native `on_micro_batch`
после выдачи каждого collated batch, с учётом dataloader prefetch. Нулевые
dummy losses служат только потреблению FIFO и не публикуются как измерения.
Требуются single process, epoch0, IndexRecordingSampler(RandomSampler),
64 batches и ровно одна permutation всех 256 rows. Python shuffle/randperm
вместо native sampler отсутствует. Записываются все row_indices и order hash.

`--reference-result` дополнительно сравнивает **каждый** batch с сохранённым
full2: порядок rows, shifted supervised tokens per row из Rewind и cumulative
real tokens из trainer log. При несовпадении measurement получает ok=false.
Это cross-check этих трёх величин, не независимый oracle для S_max.

## Что считается

Для каждого native collated batch используются фактические attention_mask и
labels; проверяются binary nonempty right padding, ignored padding labels и
dynamic S_max без округления к другому multiple.

| Поле | Определение |
| --- | --- |
| `real_tokens` | sum(attention_mask) |
| `padded_tokens` | фактические B × S_max |
| `capacity_tokens` | B × 512, только denominator для utilization |
| `padding_ratio` | (padded − real) / padded |
| `utilization_512` | real / (B × 512) |
| `padded_utilization_512` | (B × S_max) / (B × 512) |
| `completion_tokens` | count(labels != -100), до causal shift |
| `causal_target_tokens` | count(labels[:,1:] != -100) |

Sequence lengths и обе label counts сохраняются также по каждому row.
Totals складывают числители/denominators, затем считают weighted ratios;
среднее от batch percentages не используется.

### Что действительно пропускает текущий unpad/head

По actual `solution/autograd.py` и `solution/kernels/cross_entropy.py`:
decoder вычисляет только реальные позиции; **head forward также вычисляет
все реальные позиции**, потому что entropy/argmax нужны и для ignored labels.
Только head **backward** compacts shifted nonignored targets. Поэтому фраза
«head only label tokens» относится к backward, а не ко всему head.

- `decoder_skip_fraction = head_forward_skip_fraction = (padded-real)/padded`.
- `head_backward_skip_fraction = (padded-causal_targets)/padded`.
- `head_backward_skip_vs_real_fraction = (real-causal_targets)/real`.

Это fractions **token positions** при допустимом unpad path, не обещания
пропорционального wall-time, attention FLOPs или GPU-memory выигрыша.

## Время и artifacts

`token_stats.json` содержит schema/version/source hashes, config/data hashes,
tokenizer identity, resolved settings/collator/sampler, 64 per-step records,
totals, timings и optional reference check. При ошибке сохраняется валидный
JSON с ok=false/error и ненулевым exit code.

Отдельные wall intervals: imports, tokenizer load (включая cache/network),
Soup load/normalization, Soup tokenization+mask maps, TRL preparation/truncate,
collate+iterate+accounting и total. `dataset_build_s` — сумма трёх dataset
фаз, без tokenizer download и imports. Выводится короткая таблица первых/
последних batches и totals; полный per-step результат остаётся в JSON.

## CPU runner

Существующие modes не изменены. Новый `--mode tokstats` генерирует CPU-only
notebook из проверенного archive/logging bootstrap исходного template:

- `enable_gpu=false`, поле `machine_shape` отсутствует.
- `kernels push` **не получает `--accelerator`**; существующие GPU modes
  сохраняют NvidiaTeslaT4.
- Нет nvidia-smi, model/GPU warmup, harness train или solution.apply.
- CPU-index torch request и закреплённые зависимости; native
  `task/prepare_data.py` готовит тот же public split, исходный файл не меняется.
- CUDA_VISIBLE_DEVICES пуст, Accelerate use_cpu=True, итоговая проверка
  cuda.is_initialized=False; solution imports запрещены.
- Experiment --env отвергается для tokstats. Source SHA/archive hashes
  проверяются прежним bootstrap, artifacts остаются в out.

CPU job не требует GPU reservation и не использует GPU текущих A/B.
