# EXP-014 — отдельная startup/save/exit probe

Реализован runner mode `startprobe`. Он запускает **один** instrumented
official solution train и сохраняет JSON phase table, исходные timestamps
и top 30 imports. Это диагностический запуск; его wall/peak нельзя принимать
за jury timing или A/B evidence. Коммитов и запусков Kaggle исполнитель не делал.

## Запуск и неизменность official path

`tools/kaggle/start_probe.py` использует read-only official helpers:

- `harness.run_task.warm_up`: штатные imports + snapshot download до пробы.
- `make_config`: тот же task YAML, `data/train.jsonl`, seed из task (1),
  новый output adapter path. Task/harness files не редактируются.
- `OFFLINE_ENV`: GPU 0, PCI ordering, `expandable_segments:True`, offline HF,
  unbuffered output, TOKENIZERS_PARALLELISM=false, SOUP_NO_AUDIT_LOG=1.
- Тот же per-run SOUP_DB_PATH/TRITON_CACHE_DIR/TORCHINDUCTOR_CACHE_DIR,
  пустые в новом output directory.

Команда дочернего train:

```text
python -X importtime harness/_train.py --config <generated task.yaml> --metrics <metrics.json> --solution
```

`_train.py` сам вызывает официальный `soup train --config ... --yes` и
`solution.apply()` в обычном месте. Evaluation и второй train не запускаются.
В окружение только этой пробы добавляются временный shim в PYTHONPATH,
repository root, event path и owner PID. Существующий PYTHONPATH сохраняется;
найденный исходный filesystem `sitecustomize` исполняется как обычно.
Унаследованный PYTHONPROFILEIMPORTTIME очищается: profiling включён явно
через parent `-X importtime`, не через env для всех потомков.

Shim и observer существуют только в tools/ и временном каталоге subprocess.
Обычные `solution/full/full2/ab` не получают эти hooks/env/flags.
`solution/`, `harness/`, `task/`, root/solution tests не изменены.

## События и phase table

`sitecustomize` устанавливает MetaPath finder только для конечного списка
интересующих модулей. Loader делегирует исходный import, затем оборачивает
уже определённые функции. Нет eager импорта torch/transformers/trl/peft/bnb,
разрешения LazyModule attributes или загрузки модели ради instrumentation.
Используются `vars(module/class)`, сохраняются classmethod/staticmethod,
обычные return values и исключения; ошибки observer видны отдельно.

| Фаза / boundary | Точка измерения |
| --- | --- |
| process_launch_begin / spawn_return / process_end_observed | Parent perf_counter_ns вокруг Popen/wait, включая exit/join child |
| interpreter_sitecustomize / shim_ready | Ранняя метка shim и конец установки observer |
| import.torch/transformers/trl/peft/bitsandbytes/soup_cli | exec_module start/end, включая вложенные imports |
| import.soup_cli.cli и другие target modules | Отдельные spans для существенных lazy imports |
| solution_apply | Исходная `solution.apply()` |
| model_from_pretrained | Auto factory и `PreTrainedModel.from_pretrained`, с сохранением cls |
| quantization | Transformers `Bnb4bitQuantize.convert`, BNB Params4bit._quantize/functional quantize_4bit/blockwise; вложенные spans |
| quantization_setup | HfQuantizer preprocess/postprocess |
| kbit_prepare / peft_wrap | prepare_model_for_kbit_training / get_peft_model |
| soup_setup / dataset_prepare | Soup wrapper setup и TRL prepare_dataset |
| trainer_init / dataloader_build | Transformers/TRL constructors и get_train_dataloader |
| cuda_context_init | Первый `_lazy_init`, когда torch.cuda ещё не initialized |
| train_step / first_step_begin / last_step_end | Добавленный observational TrainerCallback, все шаги |
| trainer_train / soup_train_and_save | Trainer.train и внешний Soup train, включая его save |
| save_model / adapter_save / tokenizer_save | Trainer.save_model, PeftModel.save_pretrained, tokenizer save |
| trainer_on_train_end / atexit_late_callback | Callback конца train и ранняя регистрация late atexit callback |

Events содержат монотонный ns timestamp, приблизительный соответствующий
unix_ns, PID, thread ID, span ID и error type. В JSON для каждой фазы:
число вызовов, start/end offset, inclusive sum, **wall interval union** и
число ошибок. Union не удваивает вложенные или параллельные вызовы одной
фазы; разные фазы по-прежнему могут перекрываться.

`boundary_intervals` делит observed process wall на соседние интервалы:
launch → sitecustomize → shim_ready → apply_begin/end → first/last step →
late atexit → observed exit. Их сумма равна полному observed wall; отсутствие
границ не подменяется выдуманной длительностью. Это позволяет отделить
pre-apply imports, model/trainer setup и tail после loop, а save spans уточняют tail.
Оригинальные apply_s/train_loop_s/first_step_s/median_step_s из metrics.json
выводятся рядом как метрики **этого instrumented run**.

Top 30 imports сортируются по суммарному **self_us** одного модуля;
max_cumulative_us приведён отдельно. Cumulative values вложены и не
складываются. Все raw importtime строки остаются в train.log.

## Границы точности

- Это CPU wall scopes, **без новых CUDA sync/events/kernels/tensors**.
  Quantization/save с asynchronous work не получают дополнительного GPU wait.
- Точный Py_Initialize start недоступен из sitecustomize: он ограничен
  parent launch и ранней меткой shim. Setup observer выделен отдельным interval.
- Atexit callback зарегистрирован рано и выполняется поздно по LIFO;
  это не начало всех finalizers. Python non-daemon thread shutdown может
  происходить до него. Tail нельзя целиком назвать save или atexit.
- Добавленный callback находится перед harness Probe; его step timestamps
  предшествуют штатной CUDA sync. Для сопоставления есть official metrics.json;
  callback-derived loop не объявляется точной заменой harness train_loop_s.
- Parent wait(timeout) наблюдает exit с polling latency (до десятков ms).
  process_end_observed — верхняя граница фактического exit, не kernel timestamp.
- Hooks/JSONL/importtime добавляют observer overhead. Threaded imports могут
  искажать importtime nesting; фазовые суммы не являются критическим путём.

В parent удаляется только probe-added `importtime` entry из sys._xoptions:
CPython продолжает import profiling, но multiprocessing не наследует этот
флаг. Owner PID не даёт compiler/worker children устанавливать observer.
Таким образом top-import table не смешивает parent с compiler child;
дочерние процессы и их время по-прежнему участвуют в parent exit/wall.

Missing required phases, observer errors, незакрытые spans, malformed events,
ошибка metrics.json или ненулевой exit дают `ok=false` и ненулевой exit tool.
Пропавшие hooks не объявляются нулевыми длительностями.

## Артефакты и runner

В `out/startprobe_run/` сохраняются:

- `start_probe.json`: phase table, boundary intervals, timestamps, coverage,
  hook targets, official callback metrics и top imports.
- `events.jsonl`: raw parent/child observations.
- `train.log`: полный stdout/stderr, включая `-X importtime`.
- `metrics.json`, `task.yaml`, `probe_config.json`, `warmup.log`, `experiments.db`.

`probe_config.json` записывает только фиксированный allowlist технических env,
не весь process environment. Adapter/Triton/Inductor caches удаляются;
notebook finally повторяет cleanup даже после сбоя инструмента.
Metadata нового mode — private T4, обычный package/bootstrap/source verification.
Runner summary печатает таблицу после скачивания. Исходный iterate.ipynb
не редактировался: дополнительная ветка вставляется только при рендере startprobe.
